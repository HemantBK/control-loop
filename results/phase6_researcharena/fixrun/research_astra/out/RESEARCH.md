## 2. Hugging Face cache and revision resolution

### Version actually relevant

- **Verified:** transformers **4.53.3 does not pin a unique hub version**: its metadata requires `huggingface-hub>=0.30.0,<1.0`. The supplied pod log explicitly records **huggingface_hub 0.36.2**; that is the implementation audited below. Sources: [PyPI metadata](https://pypi.org/pypi/transformers/4.53.3/json); local `/home/astra/context/05_runs/debug8/steps/070156_hf_transfer.log:2`. **Inferred:** pin/log both packages; do not assert every install of transformers 4.53.3 resolves identically.

### Cache root is not the home directory convention

- **Verified:** hub 0.36.2 computes `HF_HOME` (default `~/.cache/huggingface`, honoring `XDG_CACHE_HOME`), then default hub root **`$HF_HOME/hub`**. `HF_HUB_CACHE` overrides that root, with legacy `HUGGINGFACE_HUB_CACHE` as its fallback. An explicit `cache_dir` is used **as the root itself**, without appending `/hub`; these defaults are only consulted when it is `None`. Sources: [constants lines 128–155](https://github.com/huggingface/huggingface_hub/blob/v0.36.2/src/huggingface_hub/constants.py#L128-L155), [snapshot lines 136–148](https://github.com/huggingface/huggingface_hub/blob/v0.36.2/src/huggingface_hub/_snapshot_download.py#L136-L148).
- **Verified:** under that root, normal Linux cache layout is `models--OWNER--REPO/{blobs,refs,snapshots}`; `refs/main` contains a commit SHA, while `snapshots/SHA/<filename>` normally symlinks into `blobs`. Snapshots can be partial. `local_dir=` instead produces a working file tree and its own metadata, not this cache-root layout. Source: [hub file-download layout](https://github.com/huggingface/huggingface_hub/blob/v0.36.2/src/huggingface_hub/file_download.py#L840-L872).
- **Verified:** both supplied task versions use `HF_HOME` directly as `config.hf_cache_dir`; `bench.py` passes this explicit value to **both** tokenizer and model and passes no revision. The debug8 setup log instead reports TinyLlama under `/workspace/hf/hub/models--TinyLlama--TinyLlama-1.1B-Chat-v1.0/snapshots/fe8a4ea1ffedaf415f4da2f062534de366a451e6`, with `HF_HOME=/workspace/hf`. Sources: local `/home/astra/ResearchArena/58776e0/settings/cuda_kernel/task_context/config.py:50-53`; `/home/astra/ResearchArena/11ea904/settings/cuda_kernel/task_context/config.py:59-62`; [bench lines 36–60](https://github.com/aisa-group/ResearchArena/blob/11ea904dc4439732569956750186b726ab0c830e/settings/cuda_kernel/task_context/bench.py#L36-L60); `/home/astra/context/05_runs/debug8/pods/43em5jpg85usuv/setup.log:27`.
- **Inferred:** this is a genuine lookup-root mismatch, independent of revision problems. Setting only `HF_HUB_CACHE` cannot override the benchmark's explicit `cache_dir`. For an unchanged benchmark, stage with `snapshot_download(..., cache_dir=os.environ['HF_HOME'])`; if other tools omit `cache_dir`, also set `HF_HUB_CACHE=$HF_HOME`. Alternatively later change the harness to use one explicit hub-root value consistently. Do not set `HF_HOME` to an existing `/hub` directory and then let download defaults append another `/hub`. Sources: the preceding config/bench and hub-default code.

### Offline behavior and refs

- **Verified:** `HF_HUB_OFFLINE=1` selects a hub HTTP adapter that raises `OfflineModeIsEnabled`; transformers detects hub offline mode and forces cached-file resolution to `local_files_only=True`. `local_files_only=True` is per-download/load cache-only behavior, not an environment-wide network ban. Defaults/offline flags are read into module constants; set environment **before imports/process start**. Sources: [offline adapter](https://github.com/huggingface/huggingface_hub/blob/v0.36.2/src/huggingface_hub/utils/_http.py#L105-L120), [constants](https://github.com/huggingface/huggingface_hub/blob/v0.36.2/src/huggingface_hub/constants.py#L128-L165), [transformers offline handling](https://github.com/huggingface/transformers/blob/v4.53.3/src/transformers/utils/hub.py#L410-L440), [snapshot cache-only path](https://github.com/huggingface/huggingface_hub/blob/v0.36.2/src/huggingface_hub/_snapshot_download.py#L159-L239).
- **Verified:** `snapshot_download(revision=FULL_40_HEX_SHA, cache_dir=C)` writes files under `C/models--.../snapshots/SHA` (normally backed by blobs). It writes a named ref **only if the requested revision differs from the resolved SHA**. Therefore a full-SHA download does **not create/update `refs/main`**; preexisting refs are not repaired. A named revision such as `main` or a tag writes that named ref. Source: [snapshot lines 288–312](https://github.com/huggingface/huggingface_hub/blob/v0.36.2/src/huggingface_hub/_snapshot_download.py#L288-L312).
- **Verified:** a later fresh unpinned `from_pretrained(REPO, cache_dir=C)` resolves default `main`. Offline it needs `refs/main -> SHA` and the requested snapshot files; it does **not pick the newest/only snapshot**. A full SHA resolves directly. Online an unpinned load can query current main and download a different commit. Sources: [file-download defaults](https://github.com/huggingface/huggingface_hub/blob/v0.36.2/src/huggingface_hub/file_download.py#L950-L960), [offline resolution](https://github.com/huggingface/huggingface_hub/blob/v0.36.2/src/huggingface_hub/file_download.py#L1069-L1121), [cache lookup explicitly refuses random revisions](https://github.com/huggingface/huggingface_hub/blob/v0.36.2/src/huggingface_hub/file_download.py#L1371-L1411).

**Implication — inferred:** preflight **both root and revision**. Prefer passing the same full revision to tokenizer/model, or loading the returned snapshot directory directly (local paths bypass repo-ref lookup: [transformers hub lines 419–437](https://github.com/huggingface/transformers/blob/v4.53.3/src/transformers/utils/hub.py#L419-L437)). If retaining the unchanged unpinned bench, intentionally stage and verify `refs/main` equals the approved SHA in its exact cache root; fetching `main` is not an immutable pin, and manually mapping it is an explicit harness choice to document. Verify required weight/tokenizer files and symlink targets, not just directory existence: offline `snapshot_download` can return a partial snapshot without completeness validation ([source](https://github.com/huggingface/huggingface_hub/blob/v0.36.2/src/huggingface_hub/_snapshot_download.py#L200-L218)). Run the eventual offline load preflight in a fresh process before paying for GPU time.

## 3. transformers 4.53.3 Llama/GQA and repeated injections

### Exact order and shapes

- **Verified:** `LlamaModel` computes shared cos/sin once via `self.rotary_emb(hidden_states, position_ids)` before decoder layers. Each attention layer projects/transposes q/k/v, calls module-global **`apply_rotary_pos_emb`**, updates the KV cache, then dispatches its attention implementation. Eager attention and **4.53.3 SDPA** explicitly call `repeat_kv` after that update; SDPA then calls `F.scaled_dot_product_attention`. Sources: [model lines 410–431](https://github.com/huggingface/transformers/blob/v4.53.3/src/transformers/models/llama/modeling_llama.py#L410-L431), [attention lines 228–255](https://github.com/huggingface/transformers/blob/v4.53.3/src/transformers/models/llama/modeling_llama.py#L228-L255), [eager repeat](https://github.com/huggingface/transformers/blob/v4.53.3/src/transformers/models/llama/modeling_llama.py#L155-L178), [SDPA repeat/call](https://github.com/huggingface/transformers/blob/v4.53.3/src/transformers/integrations/sdpa_attention.py#L40-L74). This statement is scoped to those paths/version, not every attention backend.
- **Verified from supplied trace:** TinyLlama has 32 query heads, 4 KV heads, head dimension 64; recorded SDPA inputs have 32 heads after expansion. Source: local `/home/astra/context/06_evidence_gqa/trace_4.53.3.json:2-40`. **Inferred from the order above:** decode RoPE sees q `[B,32,1,64]`, k `[B,4,1,64]`; cache storage remains at 4 KV heads, and SDPA sees expanded k/v `[B,32,T,64]`. A probe at SDPA cannot rule out a smaller k launch at RoPE.
- **Verified:** direct forward defaults `cache_position` to an integer range from cached length through the new tokens, shape `[S_new]`; default `position_ids=cache_position.unsqueeze(0)`, shape `[1,S_new]`. `generate` with an attention mask instead derives per-batch positions as `mask.long().cumsum(-1)-1`, fills pad positions with 1, and slices to the new input length; cache position advances independently. Sources: [Llama defaults](https://github.com/huggingface/transformers/blob/v4.53.3/src/transformers/models/llama/modeling_llama.py#L407-L431), [generation positions](https://github.com/huggingface/transformers/blob/v4.53.3/src/transformers/generation/utils.py#L601-L629), [cache advance](https://github.com/huggingface/transformers/blob/v4.53.3/src/transformers/generation/utils.py#L988-L1005), [initial cache positions](https://github.com/huggingface/transformers/blob/v4.53.3/src/transformers/generation/utils.py#L1798-L1823).
- **Inferred example:** after an unpadded prompt of length P, first one-token decode uses `cache_position=[P]` and `position_ids=[[P]]` (subsequently P+1, etc.), not zero. For padded batches, generated `position_ids` can differ per row while cache slots include padding; do not substitute cache indices for semantic positions. The upstream hook records the correct tensor before any layer calls RoPE and expands `[1,S]` to `[B,S]` when needed. Sources: preceding generation/model code and [hook lines 157–184](https://github.com/aisa-group/ResearchArena/blob/11ea904dc4439732569956750186b726ab0c830e/settings/cuda_kernel/task_context/inject.py#L157-L184).

### Two injections: last global patch wins; position hooks are model-local

- **Verified:** stock injection saves the *currently installed* global function as fallback; two calls therefore chain fallbacks. `11ea904` adds `_arena_original_apply_rope` once and always uses that stored function, avoiding a second wrapper falling back into the first wrapper **provided the first saved function really was native HF**. Every injection still unconditionally assigns the module-global symbol, and each captures its own `current_positions` dictionary populated only by that model's rotary-forward hook. Sources: [stock lines 146–173](https://github.com/aisa-group/ResearchArena/blob/58776e09339c1714d0524130590abaf6eac7879d/settings/cuda_kernel/task_context/inject.py#L146-L173), [new lines 148–193](https://github.com/aisa-group/ResearchArena/blob/11ea904dc4439732569956750186b726ab0c830e/settings/cuda_kernel/task_context/inject.py#L148-L193).
- **Inferred, two different models A then B:** all Llama attention calls now use **B's ops/base/position dictionary**, even on A or on a newly loaded nominally vanilla model. B itself works sequentially because B's rotary hook updates that dictionary first. Running A after injecting B does not update B's dictionary: if empty, lookup raises and silently falls back; if populated, stale B positions can be reused (or a shape failure falls back). Native fallback pinning prevents wrapper chaining, **not** cross-model state leakage. Sources: new hook/global assignment above and [Llama global lookup](https://github.com/huggingface/transformers/blob/v4.53.3/src/transformers/models/llama/modeling_llama.py#L235-L241).
- **Inferred, same model injected twice:** the rotary-forward wrappers nest, so both dictionaries are updated when that model runs; the last global RoPE wrapper/ops are used. It is not idempotent, though native-pinned fallback avoids recursively applying the prior RoPE wrapper. Other wrappers (notably attention) also nest if re-injected. Source: [new injection lines 94–193](https://github.com/aisa-group/ResearchArena/blob/11ea904dc4439732569956750186b726ab0c830e/settings/cuda_kernel/task_context/inject.py#L94-L193).
- **Verified compatibility caveat:** native 4.53.3 signature is `(q,k,cos,sin,position_ids=None,unsqueeze_dim=1)`; injection's signature omits `position_ids` and fallback passes `unsqueeze_dim` as positional argument five, i.e. native's deprecated/unused `position_ids`. Default Llama calls use four arguments, so default dimension 1 still works; **inferred:** non-default dimensions or keyword `position_ids` are not faithfully supported. Sources: [native function](https://github.com/huggingface/transformers/blob/v4.53.3/src/transformers/models/llama/modeling_llama.py#L112-L136), [injected function/fallback](https://github.com/aisa-group/ResearchArena/blob/11ea904dc4439732569956750186b726ab0c830e/settings/cuda_kernel/task_context/inject.py#L174-L192).

**Implication — inferred:** use fresh processes for vanilla/control/baseline/agent arms, or implement explicit verified restoration/ownership later; reloading weights alone does not restore a Python module-global patch (`restore_model` is a no-op: [source](https://github.com/aisa-group/ResearchArena/blob/11ea904dc4439732569956750186b726ab0c830e/settings/cuda_kernel/task_context/inject.py#L233-L239)). If using upstream's sequential one-process benchmark, compute vanilla first, finish A before injecting B, and never reuse A afterward. Its fresh-model B injection can work, but repeated benchmark invocations in one interpreter need isolation. Require call counters/fallback diagnostics plus prefill/decode correctness checks: “INJECTED” alone only confirms assignment, while exceptions silently route to fallback ([source](https://github.com/aisa-group/ResearchArena/blob/11ea904dc4439732569956750186b726ab0c830e/settings/cuda_kernel/task_context/inject.py#L174-L193)).
