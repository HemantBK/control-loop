    43	## CUDA Pitfalls — AVOID THESE
    44	
    45	These are common errors that will break compilation or produce wrong results:
    46	
    47	### Host functions in device code
    48	**`__builtin_prefetch` is a HOST function.** You CANNOT call it from a `__global__` or
    49	`__device__` function. NVCC will reject it. If you want prefetching in CUDA, use:
    50	- Shared memory staging instead of prefetch
    51	- `__ldg()` for read-only cache hints
    52	- `cp.async` (SM80+) for async global→shared copies
    53	
    54	### float4 alignment
    55	`reinterpret_cast<float4*>(ptr)` requires 16-byte aligned pointers. Half-precision
    56	(`__half`) data is 2 bytes per element, not 4. Do NOT cast `__half*` to `float4*`.
    57	For fp16 vectorization, use `__half2` instead.
    58	
    59	### Attention Q/K shape mismatch
    60	During autoregressive generation with KV cache, Q has `seq_len=1` (the new token) while K
    61	and V have the **full accumulated sequence length**. The starter attention kernel handles this
    62	with separate `q_len` and `kv_len` parameters. **Do NOT collapse these into a single `seq_len`.**
    63	If your kernel assumes `Q.size(2) == K.size(2)`, it will compute wrong strides for K/V and
    64	cause an illegal memory access during generation. Always use separate dimensions:
    65	- `q_len = Q.size(2)` for Q strides and grid dimensions
    66	- `kv_len = K.size(2)` for K/V strides, score arrays, and iteration bounds
    67	
    68	### Shared memory limits
    69	- H100: 228 KB per SM (configurable), default ~48 KB per block
    70	- Do NOT allocate `seq_len * sizeof(float)` in shared memory for seq_len > 12000
    71	- Use tiling: process data in fixed-size tiles (e.g., TILE_SIZE=128)
    72	
    73	### Thread count and register pressure
    74	- Block sizes > 512 cause register spilling → performance collapse
    75	- Start with 256 threads, only increase if occupancy analysis justifies it
    76	- Use `__launch_bounds__(maxThreads)` to help the compiler
    77	
    78	### Other common errors
    79	- `atomicAdd` on `__half` requires SM60+ and special overloads
    80	- `__syncthreads()` inside divergent branches → deadlock
    81	- Writing to `const __restrict__` pointers → undefined behavior
    82	- Missing `__syncthreads()` between shared memory write and read → race condition

    57	For fp16 vectorization, use `__half2` instead.

    59	### Attention Q/K shape mismatch
    60	During autoregressive generation with KV cache, Q has `seq_len=1` (the new token) while K
    61	and V have the **full accumulated sequence length**. The starter attention kernel handles this
    62	with separate `q_len` and `kv_len` parameters. **Do NOT collapse these into a single `seq_len`.**
    63	If your kernel assumes `Q.size(2) == K.size(2)`, it will compute wrong strides for K/V and
    64	cause an illegal memory access during generation. Always use separate dimensions:
    65	- `q_len = Q.size(2)` for Q strides and grid dimensions
    66	- `kv_len = K.size(2)` for K/V strides, score arrays, and iteration bounds
    67	
    68	### Shared memory limits
    69	- H100: 228 KB per SM (configurable), default ~48 KB per block
    70	- Do NOT allocate `seq_len * sizeof(float)` in shared memory for seq_len > 12000
    71	- Use tiling: process data in fixed-size tiles (e.g., TILE_SIZE=128)
    72	
    73	### Thread count and register pressure
    74	- Block sizes > 512 cause register spilling → performance collapse
    75	- Start with 256 threads, only increase if occupancy analysis justifies it
    76	- Use `__launch_bounds__(maxThreads)` to help the compiler
    77	
    78	### Other common errors
    79	- `atomicAdd` on `__half` requires SM60+ and special overloads
    80	- `__syncthreads()` inside divergent branches → deadlock
    81	- Writing to `const __restrict__` pointers → undefined behavior
    82	- Missing `__syncthreads()` between shared memory write and read → race condition
